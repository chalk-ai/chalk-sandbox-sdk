- send `chalk.environment_id` as W3C baggage on outbound calls, so a shared service can attribute the call it is serving to an environment. Locally the id belongs on the span's *resource*, which the remote-call runtime sets from `CHALK_ENVIRONMENT_ID` — correct because one function process serves exactly one environment. A shared service is the opposite case: one deployment serves every environment, and an OTel resource is built once per process, so nothing it puts there can be right per call. The id is added at injection rather than attached to the local context, so it rides the wire without being duplicated onto every local span. Interim by design — baggage makes this caller-asserted, so it is an attribution hint rather than a tenancy boundary; META-533 tracks moving the shared-service side to the request's JWT principal.
