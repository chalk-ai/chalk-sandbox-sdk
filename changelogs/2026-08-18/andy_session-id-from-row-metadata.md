- Resolve a call's session from the row's metadata as well as the request's header. `catalog_call('fn', ..., row_metadata => <binary expr>)` is the only per-row channel — a header is per request, so a batch whose rows belong to different conversations cannot say so with one — but the blob was opaque, leaving every function to parse it and reach into `chalkcompute._tracing` for the private `enter_session` to do anything with it. A blob that parses as a UTF-8 JSON object naming a `__chalk__session_id__` now places that row's spans in that session, exactly as `x-chalk-session-id` does for the whole request, and the row wins when both are present: it is the more specific of the two, and a header cannot disagree between rows of one request anyway. Everything else about the blob stays opaque — it is still readable verbatim through `chalkcompute.get_row_metadata()`, and one that is not JSON, not an object, or does not name the key leaves the row to the header rather than failing it.
