- Fix the session-stamping span processor never reaching an exported span in a remote function pod. `enter_session` attached it to the tracer provider chalkcompute builds and recorded "installed" process-wide; but the `chalk-remote-call` runtime installs its own provider first, so `set_tracer_provider` was refused ("Overriding of current TracerProvider is not allowed") and chalkcompute's was orphaned — and that one flag then suppressed the install on the live provider, so no span was ever stamped with `session.id`. The processor is now tracked per provider, and an already-installed provider is adopted instead of building a second one whose exporter nothing would reach.
- Give each session its own trace. Chalk resolves the session of a whole trace as a `max()` over its spans' `session.id`, while one remote call serves a whole batch of rows under a single invocation span — so rows naming different sessions collapsed into whichever id sorted highest, taking the session-less rows with them. `enter_session` now roots the session in a new trace under a `chalkcompute.session` span, linked back to the enclosing call span so the fan-out stays navigable from either end. Re-entering the session already in scope joins it, so a nested compute function does not split the conversation, and a session that emits no spans of its own is now visible instead of invisible.
