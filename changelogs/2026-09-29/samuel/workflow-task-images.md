- Add `@task(image=cc.Image(...))` support to `chalkcompute.run_workflow` and `chalkcompute.deploy_workflow_worker`: each distinct task image gets its own scale-to-zero worker, `<worker>-<image hash>`, and the workflow runs those tasks there as child workflows, so the image's group is up only while one of its tasks runs. `WorkflowWorker.task_workers` maps each such task to its group. Requires a chalkpy with `@task(image=...)`. Task workers of images a redeploy no longer uses are deleted. `worker_requirements` now keeps a script's other chalkpy extras alongside `workflows`, and a local checkout (version `0.0.0`) no longer pins an unpublishable version. A missing `add_local_file(strategy="volume")` source is reported when the image is used by a sandbox, function, or scaling group, alongside the existing destination check, rather than at construction, so a worker re-importing a file whose task image names local files does not fail on them. A task image installs only the runtime (`chalkpy[workflows]`, `chalkcompute`) on top of the task's own packages, not the script's other dependencies. Task workers are tagged `chalk.workflow-worker=<worker>`, and cleanup goes by that tag.
