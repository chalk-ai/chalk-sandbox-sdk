- Enforce `call_timeout` in the native Rust remote-call client instead of a Python-side thread watchdog. `chalk_remote_call_client` (chalk-ai/chalk-private#43168) now wraps its gRPC calls in `tokio::time::timeout`, which drops the call and tears down the underlying HTTP/2 stream on expiry — real cancellation, rather than the previous approach of abandoning a daemon thread while the hung call kept running server-side. `_ensure_remote_call_client` passes `call_timeout` down as `call_timeout_ms`; `_with_remote_call_transport` no longer spawns a thread per call, and a `TimeoutError` from either the native client or the gRPC-stub fallback path is enriched with the scaling group's status in one place instead of only when the (now-removed) Python watchdog itself fired the timeout.
