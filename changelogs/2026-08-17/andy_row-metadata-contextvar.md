- Surface what a caller attached to the invocation in progress, without the function declaring a parameter for it: `chalkcompute.get_call_context()` returns the request's gRPC headers (the `context` the runtime already hands the handler, which the shims previously discarded), and `chalkcompute.get_row_metadata()` returns the per-row blob Chalk sends via `catalog_call(..., row_metadata => <binary expr>)` under the reserved `__chalk_row_metadata__` column. Both are optional in both directions — a caller may send neither, and a function may read neither — and both are published by the function, batched-function, and `@cls` handler shims. Batched calls carry both per work item, so they stay correct across the shim's thread pool and asyncio tasks, where the context is per coalesced caller. Images built in strip mode do not install `chalkcompute`, so the shim degrades to publishing nothing rather than failing the call.
